- (decision) Source set confirmed by user: use the product brief and addendum, final Muvdash PRD and addendum, and \_bmad-output/api_structure.md as UX context. User chose coaching discussion and explicitly does not want visual examples; discuss UI/UX considerations directly.
- (decision) Homepage/layout: when opening on phone, users see a friendly dashboard with the movie list. Header contains route navigation and a logo at the start; clicking the logo navigates to Dashboard. Grid target: 2 movies per row on mobile, 4 on tablet, 6 or more on desktop. Visual direction: friendly, nice fonts, muted/faded warm colors; avoid shiny, strident colors. Main colors are purple and turquoise, with restrained faded-orange accents such as buttons or lines. Exact shades, fonts, and component styling remain undecided.
- (decision) Color hierarchy confirmed: purple is the primary color, turquoise is secondary, and orange is tertiary; all should remain muted/faded, warm, and non-strident.
- (decision) Typography direction: readable, modern, simple, and easy to understand; avoid ornate/fancy fonts and oversized type. Use compact type sizing so more movie information fits in the available space without sacrificing readability. Exact font family and scale remain undecided.
- (decision) Header/navigation: on mobile, show a burger/menu icon; activating it reveals an animated navigation list with route options. On tablet and desktop, show navigation items on the right side of the header. Place the app logo on the left at all sizes; activating the logo navigates to Dashboard/Home.
- (decision) Mobile menu dismissal: the expanded navigation closes when the user clicks outside it, presses its top-right X close button, or selects a route. The X is part of the menu overlay/panel.
- (decision) Search placement/scroll behavior: the search starts visible below the header. As the user scrolls, it sticks beneath the header and remains visible. In sticky state it becomes more compact, with clear spacing between the input and header.
- (decision) Details modal: keep it centered across breakpoints and size it to use most of the available viewport when needed. On phones, typography is smaller than tablet/desktop to keep all information visible without scrolling where possible; allow modal-content scrolling only for extreme/necessary cases.
- (decision) Movie card visual hierarchy: image is the primary attention point, followed by the movie title, then description and the other summary information.
- (decision) New UX feature: place a small view-toggle icon after the search input. Default to portrait movie cards using the portrait image field. Activating the icon switches to a landscape presentation using the landscape movie image; activating again switches back. Change the icon to reflect the active portrait/landscape view. Arrange information clearly in both views.
- (decision) Responsive card density applies in both portrait and landscape views: 2 cards per row on mobile, 4 on tablet, and 6 or more on desktop. Landscape mode remains a multi-column card layout.
- (decision) Tooltip interaction: users activate tooltips by click/tap, including on touch devices. Trigger placement/content and dismissal behavior remain undecided.
- (decision) Tooltip dismissal: close when the user clicks/taps outside, activates the same icon again, or performs another action such as changing route.
- (decision) Accessibility baseline: Muvdash follows WCAG 2.2 AA.
- (decision) Voice and tone: use the same friendly, playful tone throughout the interface, including navigation, general guidance, and state messages.
- (decision) Details modal content requested: movie description, director, producer, release date, running time, score, people, species, locations, and vehicles, using data from the API. Retain the previously confirmed movie image/title as the lead visual and title. Exact field grouping/order and treatment of raw IDs/URLs remain to clarify.
- (decision) Details modal scope clarified: omit raw IDs and raw API URLs from display. Use URLs contained in API data only to fetch associated information for presentation; show resolved data instead of URL strings. Requested visible fields are description, director, producer, release date, running time, score, people, species, locations, and vehicles, alongside the film image/title.
- (decision) Details completeness: if a requested detail field is absent from the API response, omit that field entirely rather than showing a placeholder.
- (decision) Theme feature: default to dark theme. Provide an always-visible sun/moon toggle in the header; on mobile it appears before the hamburger menu, and on tablet/desktop after the final navigation item. Activating it switches light/dark theme and saves the selected theme to localStorage. On startup, read localStorage and apply its saved preference; if none exists, use dark. Theme colors adapt to the active mode.
- (decision) Theme control clarified: use a two-option switch with one theme on each side, showing sun/moon iconography. The active theme option is more highlighted; activating either option selects that theme. This replaces the single-toggle-icon concept. Vuetify is added to the planned Vue 3 client stack as the component/UI system, alongside Vite, TypeScript, Pinia, and Vue Router; use its components. Package installation is deferred until app implementation because no app scaffold exists yet.
- (decision) Theme switch order/icons: Light with sun icon on the left; Dark with moon icon on the right. Highlight the active side. Dark remains the default unless localStorage contains a saved preference.
- (decision) Palette role direction: muted purple is most visible on app backgrounds/surfaces, with purple shades used for borders. Turquoise is the preferred text color; purple and orange may be used on buttons. Every text/background combination must meet the WCAG 2.2 AA contrast target. Exact role allocation and shades remain to clarify.
- (decision) Turquoise text direction refined: use a light turquoise that contrasts with purple, primarily for movie titles; do not assume turquoise for all text. Exact shades must meet WCAG 2.2 AA. Body-description and other text colors remain undecided.
- (override) New text-contrast direction: use white text on purple backgrounds. This may supersede the earlier light-turquoise movie-title preference; confirm whether turquoise titles are an exception or should also be white on purple.
- (decision) Text color roles clarified for purple backgrounds: movie titles and descriptions use light turquoise; all other text uses white. Both turquoise and white text on purple must satisfy WCAG 2.2 AA contrast.
- (decision) Light theme direction: use a light turquoise color predominantly for backgrounds/surfaces and purple for text, reversing the dark-theme surface/text relationship. Exact shades remain open; all combinations must meet WCAG 2.2 AA.
- (decision) In light theme, movie titles and descriptions are purple, along with other text. This reverses the dark-theme title/description treatment, which uses light turquoise on purple surfaces.
- (decision) Card image treatment: keep all cards the same size; fill the image area and crop the image centered when necessary. Apply this to both portrait and landscape card modes.
- (decision) Header behavior: keep the header visible/sticky at the top while scrolling on mobile, tablet, and desktop. The search remains visible and sticky directly below the header, compacting on scroll.
- (question) User wants all planned animations shown for now. Clarify whether this also overrides a device's reduced-motion preference, because accessibility baseline is WCAG 2.2 AA; distinguish normal animation behavior from reduced-motion behavior before finalizing.
- (decision) Motion accessibility: show planned animations normally. When the device has reduced motion enabled, reduce the animations rather than playing them unchanged; exact reduction behavior is open.
- (decision) Reduced-motion treatment: when the device requests reduced motion, keep transitions subtle rather than removing them entirely.
- (decision) Header logo: use the text 'MuvDash' as the logo for now; no separate graphic mark is specified.
- (question) Navigation naming clarification: user replied 'use only Home, in the implementations, and text for routes.' Confirm interpretation: label the Home route 'Home' (not Dashboard), and use text labels for Home, Contact, and About rather than route icons.
- (decision) Route navigation labels: use text labels Home, Contact, and About; no icons for route items. The logo text is MuvDash and navigates to Home.
- (decision) Landscape card layout: place the wide image above the movie information, preserving the established image-first, title-second hierarchy.
- (override) Card-content override: portrait and landscape cards show only the image, title, and description. Trim card descriptions to a maximum of two rows. Do not show release date or producer on cards; those details remain available in the details experience. This supersedes the earlier PRD card-field requirement; synchronize PRD and PRD addendum.
- (decision) Details modal information order confirmed: after the film image and title, show description, director, producer, release date, running time, score, then related people, species, locations, and vehicles.
- (decision) Shape direction: all cards and buttons use very softly rounded corners. Modal corner treatment remains to confirm.
- (decision) The centered details modal uses the same very softly rounded corners as the movie cards and buttons.
- (decision) Movie cards use a restrained, elegant, soft shadow; avoid heavy shadowing. Purple-shaded borders and the soft shadow can both be used, with exact visual balance left for token/component detail.
- (decision) The centered details modal uses the same restrained, elegant, soft shadow as movie cards.
