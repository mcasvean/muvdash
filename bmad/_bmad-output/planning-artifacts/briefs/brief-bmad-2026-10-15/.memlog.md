- (decision) Initial concept: small client-side movie dashboard using Vue, Vite, TypeScript, Pinia, and Vue Router; three routes (home, contact, about); fetch the movie list on dashboard mount; display movie cards with title, release year/date, image, description, and producer; expand a card into a centered modal with all fields from _bmad-output/api_structure.md; close button; client-side search across title, release_date, producer, director, and description because the full list is already fetched; detailed visual design is deferred to a separate discussion. API payload contract is provided in _bmad-output/api_structure.md.
- (decision) Project stakes: personal project. Working mode: coaching path. User explicitly requests clarification instead of assumptions whenever anything is unclear.
- (decision) Motivation: a personal project for practicing and reinforcing the BMad methodology. Intended users: the user's friends, who would use it to relax and find enjoyable movies in their free time.
- (constraint) No movie playback is in scope at this point; the app is a browsable library of movie cards and details only.
- (decision) The movie catalog is limited to Studio Ghibli films represented by the API structure in _bmad-output/api_structure.md.
- (decision) Catalog source confirmed: Studio Ghibli films only. The client fetches the list with GET from https://ghibliapi.vercel.app/films; use this endpoint in the app configuration.
- (decision) Primary success criterion: practice and reinforce the BMad methodology; this is almost the only purpose. Friend-facing Ghibli browsing is secondary.
- (decision) Learning scope: the user wants to practice the full BMad flow on this project, including requirements, UX, architecture, planning, implementation, and the implementation workflow.
- (decision) Learning success: complete each BMad step and phase with enough understanding to repeat the process on other projects. Longer-term product intent: continue adding features to and maintaining this project beyond its initial scope.
- (question) Open questions for later phases: final product name; purpose/content of the Contact and About routes; visual design direction (deferred to the UX discussion). Do not infer answers in this brief.
